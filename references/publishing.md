# 产品截图与微信公众号发布

## AuraMate 产品截图

官网固定使用 `https://auramate.com.cn`。优先在用户已登录的 Chrome 标签页操作；只有用户主动提供凭据时才登录。凭据仅用于当前会话，不写入脚本、配置或仓库。

需要两张截图：

1. 财运分析：展示真实产品导航、趋势／评分／建议等界面结构。
2. 缘分测算：展示真实产品导航、关系指数／合盘／建议等界面结构。

若界面里的样例命盘与文章日主、流月不一致：

- 截取真实 UI。
- 用 `scripts/mask_product_screenshot.py` 模糊具体命盘、姓名、出生信息和样例结论。
- 保留产品名称、功能结构与使用场景。
- 不在遮罩区伪造一个“正确命盘”。

截图应裁去浏览器地址栏和无关空白。二维码上方文案固定为“扫码使用产品”，下方可写 `auramate.com.cn`。

## 保存微信公众号草稿

默认目标是草稿，不是发表。执行前确认：

- Chrome 已登录目标公众号。
- 当前存在 `mp.weixin.qq.com/cgi-bin/appmsg` 图文编辑页。
- HTML 已通过 0 ERROR、0 WARNING 校验。
- 标题、正文和图片均为本次任务产物。

macOS Chrome 需要开启“允许来自 Apple 事件的 JavaScript”。然后运行 `scripts/save_wechat_draft.jxa`。脚本不得选择封面、打开“下一步”或点击“发表”。

保存后读取编辑器并核对：

- 标题完整。
- 正文长度不是 0，且首段正确。
- 图片数量符合文章规划。
- 存在固定提示。
- 存在“扫码使用产品”。
- 封面图在正文内仍为 2.35:1。

若浏览器 DOM 已变化，停止自动点击并报告“未找到哪个元素”；不要猜测相邻按钮。

## 最终发表

发表是外部不可逆动作。只有用户当前请求明确包含“发表／发布”，才能继续。发表前在界面再次确认标题、封面和摘要；平台要求补头像、名称、主体信息或认证时，把缺项交给用户处理。不得绕过平台提示。
